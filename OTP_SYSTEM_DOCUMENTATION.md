# Uber-Style OTP System for Borrow/Lend Transactions

## Overview

This document describes the implementation of an Uber-style OTP (One-Time Password) verification system for the Student Resource Exchange platform's borrow/lend feature. Similar to how Uber uses OTP codes to verify rider pickups and drop-offs, this system ensures secure verification of item handovers and returns.

## System Architecture

### 1. **Two-Phase Verification**

#### Phase 1: Acceptance (Pickup)
- **When**: Borrower picks up the item from lender
- **OTP Generated By**: Lender (automatically when request is approved)
- **OTP Verified By**: Lender (borrower shows the OTP)
- **Purpose**: Confirms item was successfully handed over
- **Result**: Status changes from `approved` → `active`

#### Phase 2: Return (Drop-off)
- **When**: Borrower returns the item to lender
- **OTP Generated By**: Borrower (when ready to return)
- **OTP Verified By**: Lender (borrower provides the OTP)
- **Purpose**: Confirms item was successfully returned
- **Result**: Status changes from `active` → `returned`

## Database Models

### BorrowOTP Model

```python
class BorrowOTP(models.Model):
    # Relationships
    borrow_request = ForeignKey(BorrowRequest)
    
    # OTP Details
    otp_type = CharField  # 'acceptance' or 'return'
    otp_code = CharField  # 6-digit numeric code
    
    # Verification
    is_verified = BooleanField
    verified_at = DateTimeField
    verified_by = ForeignKey(User)
    
    # Security
    created_at = DateTimeField
    expires_at = DateTimeField  # 15 minutes from creation
    attempts = IntegerField  # Current verification attempts
    max_attempts = IntegerField  # Maximum 5 attempts
```

## API Endpoints

### 1. Generate Acceptance OTP
**URL**: `/products/borrow-requests/<request_id>/generate-acceptance-otp/`  
**Method**: GET  
**Permission**: Lender only  
**Status Required**: `approved`

Automatically generates acceptance OTP and sends notification to borrower.

### 2. Verify Acceptance OTP
**URL**: `/products/borrow-requests/<request_id>/verify-acceptance-otp/`  
**Method**: GET (form), POST (verify)  
**Permission**: Lender only  
**Status Required**: `approved`

Lender verifies the OTP shown by borrower to confirm pickup.

**POST Parameters**:
- `otp_code`: 6-digit OTP code

**Success Actions**:
- Status: `approved` → `active`
- `acceptance_otp_verified` = True
- `start_date` = Today
- `expected_return_date` = Today + requested_days
- Product marked as `is_currently_borrowed` = True

### 3. Generate Return OTP
**URL**: `/products/borrow-requests/<request_id>/generate-return-otp/`  
**Method**: GET  
**Permission**: Borrower only  
**Status Required**: `active`

Borrower generates return OTP when ready to return item.

### 4. Verify Return OTP
**URL**: `/products/borrow-requests/<request_id>/verify-return-otp/`  
**Method**: GET (form), POST (verify)  
**Permission**: Lender only  
**Status Required**: `active`

Lender verifies the OTP provided by borrower to confirm return.

**POST Parameters**:
- `otp_code`: 6-digit OTP code

**Success Actions**:
- Status: `active` → `returned`
- `return_otp_verified` = True
- `actual_return_date` = Today
- Product marked as `is_currently_borrowed` = False

### 5. Resend OTP
**URL**: `/products/borrow-requests/<request_id>/resend-otp/<otp_type>/`  
**Method**: GET  
**Permission**: 
  - Acceptance: Lender only
  - Return: Borrower only

Invalidates previous OTP and generates a new one with fresh expiry time.

### 6. Get OTP Status (AJAX)
**URL**: `/products/borrow-requests/<request_id>/otp-status/`  
**Method**: GET  
**Permission**: Borrower or Lender  
**Response** (JSON):
```json
{
    "success": true,
    "status": "approved",
    "acceptance_verified": false,
    "return_verified": false,
    "acceptance_otp": {
        "code": "******",  // Hidden for borrower
        "expires_in_minutes": 12,
        "attempts": 0,
        "max_attempts": 5
    }
}
```

## Utility Functions

### `otp_utils.py`

#### `generate_otp(length=6)`
Generates random 6-digit numeric OTP.

#### `create_acceptance_otp(borrow_request)`
Creates acceptance OTP for item pickup:
- Invalidates previous unverified acceptance OTPs
- Generates new 6-digit OTP
- Sets 15-minute expiry
- Caches OTP for quick lookup
- Returns BorrowOTP instance

#### `create_return_otp(borrow_request)`
Creates return OTP for item return:
- Invalidates previous unverified return OTPs
- Generates new 6-digit OTP
- Sets 15-minute expiry
- Caches OTP for quick lookup
- Returns BorrowOTP instance

#### `verify_otp(borrow_request, otp_type, entered_otp, user)`
Verifies entered OTP code:
- Checks if OTP exists and is valid
- Increments attempt counter
- Validates against max attempts (5)
- Checks expiry (15 minutes)
- Marks as verified on success
- Returns: `(success: bool, message: str, otp: BorrowOTP)`

#### `get_active_otp(borrow_request, otp_type)`
Retrieves currently active (unverified, non-expired) OTP.

#### `resend_otp(borrow_request, otp_type)`
Resends/regenerates OTP with fresh expiry.

#### `send_otp_notification(borrow_request, otp, recipient_type)`
Sends OTP via chat messaging system:
- Creates conversation between borrower and lender
- Sends formatted system message with OTP details
- Different messages for acceptance vs return
- Different messages for borrower vs lender

## Security Features

### 1. **OTP Expiry**
- All OTPs expire after **15 minutes**
- Automatic validation on verification attempts
- User-friendly error messages

### 2. **Attempt Limiting**
- Maximum **5 verification attempts** per OTP
- Counter increments on each attempt
- Prevents brute-force attacks
- User must request new OTP after max attempts

### 3. **Role-Based Access**
- Acceptance OTP: Only lender can generate and verify
- Return OTP: Borrower generates, lender verifies
- Decorators enforce permissions: `@lender_required`, `@borrower_required`

### 4. **One-Time Use**
- OTPs marked as verified after successful use
- Cannot be reused
- Previous unverified OTPs invalidated when new one generated

### 5. **Caching**
- OTPs cached for quick validation
- Cache invalidated on verification
- Reduces database queries

## User Experience Flow

### For Borrower:

1. **Request Item** → Submit borrow request
2. **Wait for Approval** → Lender reviews and approves
3. **Receive Acceptance OTP** → Get OTP via chat notification
4. **Show OTP at Pickup** → Show 6-digit code to lender
5. **Use Item** → Borrowing period starts after verification
6. **Generate Return OTP** → Click button when ready to return
7. **Provide OTP at Return** → Give 6-digit code to lender
8. **Transaction Complete** → Item marked as returned

### For Lender:

1. **Receive Request** → Review borrow request
2. **Approve Request** → Acceptance OTP auto-generated
3. **Share OTP** → OTP sent to borrower via chat
4. **Verify at Pickup** → Enter OTP shown by borrower to confirm handover
5. **Monitor Borrowing** → Item is now borrowed
6. **Receive Return OTP** → Borrower provides OTP when returning
7. **Verify at Return** → Enter OTP to confirm item received
8. **Transaction Complete** → Item available again

## Testing Guide

### Test Scenarios:

#### 1. **Happy Path - Complete Transaction**
```
1. Borrower requests item
2. Lender approves → Acceptance OTP generated
3. Lender verifies acceptance OTP → Status becomes active
4. Borrower generates return OTP
5. Lender verifies return OTP → Status becomes returned
```

#### 2. **OTP Expiry**
```
1. Generate OTP
2. Wait 16 minutes
3. Try to verify → Should fail with "OTP expired"
4. Resend OTP
5. Verify new OTP → Should succeed
```

#### 3. **Max Attempts**
```
1. Generate OTP
2. Enter wrong OTP 5 times → Should fail
3. Try 6th time → Should show "Max attempts exceeded"
4. Resend OTP
5. Verify new OTP → Should succeed
```

#### 4. **Permission Checks**
```
1. Borrower tries to verify acceptance OTP → Should fail
2. Lender tries to generate return OTP → Should fail
3. Third party tries to access → Should fail
```

#### 5. **Resend OTP**
```
1. Generate OTP (e.g., 123456)
2. Resend OTP (generates new e.g., 789012)
3. Try to verify old OTP (123456) → Should fail
4. Verify new OTP (789012) → Should succeed
```

## Error Handling

### Common Error Messages:

| Error | Cause | Solution |
|-------|-------|----------|
| "No active OTP found" | OTP not generated | Generate new OTP |
| "OTP has expired" | More than 15 min passed | Resend OTP |
| "Invalid OTP" | Wrong code entered | Check and re-enter |
| "Maximum attempts exceeded" | 5+ failed attempts | Resend OTP |
| "OTP already verified" | Trying to reuse OTP | Already completed |
| "Request must be approved" | Wrong status | Wait for approval |
| "This item is not currently borrowed" | Wrong status | Check status |

## Troubleshooting

### OTP Not Received:
1. Check chat/conversation exists
2. Verify message creation in database
3. Check user notification preferences
4. Use "Resend OTP" button

### OTP Verification Failing:
1. Verify OTP code is correct (6 digits)
2. Check if OTP has expired (< 15 min)
3. Check remaining attempts (< 5)
4. Ensure correct user role (lender vs borrower)

### Status Not Updating:
1. Verify OTP verification succeeded
2. Check database transaction committed
3. Refresh page to see updated status
4. Check server logs for errors

## Conclusion

This Uber-style OTP system provides secure, user-friendly verification for borrow/lend transactions. By requiring OTP verification at both pickup and return, it protects both parties and creates an auditable trail of item handovers.

The system is designed to be:
- **Secure**: Time-limited, attempt-limited, one-time use
- **User-friendly**: Clear messages, easy resend, chat integration
- **Reliable**: Cached for performance, indexed for speed
- **Auditable**: Full history of OTP generation and verification
